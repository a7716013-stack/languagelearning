# Phase 2 討論決定紀錄（2026-11-14）

開始實作前，與開發者逐項討論並確認的決定。後續設計文件（`01`～`10`）與 ADR 以此為準。

| # | 主題 | 決定 |
|---|---|---|
| 1 | 版本與範圍 | 一次規劃、一次發布，版號 2.1.0；不切中間版本（ADR 0005） |
| 2 | 試題內容 | 做出完整試題：至少一份 200 題原創模擬試卷，題型分布與現行 TOEIC L&R 一致（Part 1：6、Part 2：25、Part 3：39、Part 4：30、Part 5：30、Part 6：16、Part 7：54；實作前再查證） |
| 2a | 音檔 | 這次只完成腳本、題目、答案與解析，音檔之後再補；缺音檔的聽力題組標示「待補音檔」，不能發布 |
| 2b | 音檔補齊前 | 開放 Part 5～7 共 100 題的「閱讀測驗」（75 分鐘），明確標示非完整模擬考 |
| 2c | 題庫 | 練習與模擬考共用同一個題庫；記錄使用者做過的題目，模擬考開始時與成績報告中提示重複題數 |
| 2d | 審核 | Claude 先逐題自我檢查（答案唯一、誘答合理、語言自然、解析正確、不使用官方或市售題目）並做盲測複核，再由開發者抽查 |
| 2e | 圖表 | Part 3、4、7 的時刻表、價目表等由 Claude 製作，來源標示「原創」；Part 1 照片需由開發者提供自行拍攝或有授權的照片 |
| 3 | 作答模型 | 練習與模擬考共用 `ExamAttempt`（以模式區分），規則差異由各模式的規則設定處理（ADR 待寫） |
| 4 | 題目版本 | 以「題組」為單位（單題視為一題的題組）；草稿可修改，發布時凍結為不可變版本；修改已發布題組需複製成新草稿再發布；版本不可刪除，只能停用；作答快照記錄題組版本、順序、當時正確答案與計分規則版本，不複製整份內容（ADR 待寫） |
| 5 | 模擬考計時 | 先聽力後閱讀，進入閱讀後不能回到聽力；聽力音檔連續播放一次，不能暫停、重播或倒轉；聽力時間由音檔總長決定，閱讀 75 分鐘；不能暫停，關閉瀏覽器時間照算；以伺服器時間計時；截止後寬限 5 秒；逾時自動交卷；中途離開的考試於使用者回來時結算，背景服務每分鐘掃描過期考試 |
| 6 | 交卷與並行 | 狀態「作答中 → 已完成」並記錄完成原因；重複交卷回傳同一份成績；交卷可附帶最後答案並在同一交易完成；同一場作答的存答與交卷依序處理；多分頁以最後儲存為準，晚到的舊答案依序號忽略；成績與計分規則版本一起保存，不回頭重算 |
| 7 | 成績顯示 | 只顯示答對題數與答對率（總分、聽力、閱讀、各 Part）；`ScoringRule` 預留「非官方預估分數」；題目答對率累積滿 30 次作答才顯示；作答時間標示為約略值 |
| 8 | 媒體 | `IMediaStorage` 抽象；開發存本機資料夾（不放公開目錄）；圖片 JPEG/PNG/WebP ≤5 MB、音檔 MP3/M4A ≤20 MB；檢查檔頭、移除 EXIF、記錄雜湊；來源與授權必填；依草稿 / 練習 / 模擬考快照控管存取；API 串流支援 Range；音檔長度由管理者上傳時瀏覽器讀取 |
| 9 | F2-01 穩定性 | E2E 以減少動態效果模式執行並重跑 10 次驗證；資料庫寄件匣（不存 Token、非同步寄出、重試）；開發環境把信件存成 HTML 檔；路由延遲載入；開發套件弱點以 overrides 修補、不降版；`v1.0.0` 標籤由開發者建立；CI 固定 `ubuntu-24.04` |
| 9a | Email 驗證 | 保留 Email 驗證與忘記密碼寄信（曾討論移除，最後決定保留） |
